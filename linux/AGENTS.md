# Linux port

## Purpose

The Linux implementation of Dictate Unlimited: PipeWire capture, CPU-only Bark 3.0 recognition through whisper.cpp `parakeet-cli`, a long-running daemon and CLI, Wayland text insertion, and the optional voice assistant. This folder also owns the Hyprland, Waybar, systemd, model-catalog, and install surfaces.

## Ownership

Owns everything under `linux/` except the two child domains below. That includes `install.sh`, `dictate`, `models.json`, `hyprland.conf.example`, `README.md`, `TESTING.md`, `systemd/`, and `waybar/`.

## Local Contracts

- `linux/dictate` is the launcher symlink target. `install.sh` links it to `~/.local/bin/dictate` and links `linux/waybar/dictate-assistant-waybar` to `~/.local/bin/dictate-assistant-waybar`.
- `install.sh --hyprland` writes the marked block generated by `cli.hyprland_block()` into `~/.config/hypr/hyprland.conf` and creates a timestamped backup. The block includes `exec-once = dictate daemon --detach`.
- `linux/hyprland.conf.example` and the shortcut tables in `linux/README.md` must match `cli.hyprland_block()`.
- Assistant binding is only `SUPER + A` (`assistant toggle`). The toggle interrupts thinking/speaking work, so there is no `assistant cancel` bind.
- `linux/systemd/dictate-unlimited.service` runs `dictate daemon --foreground` and must keep `CUDA_VISIBLE_DEVICES`, `HIP_VISIBLE_DEVICES`, `ROCR_VISIBLE_DEVICES` empty and `GGML_CUDA=0`.
- `linux/models.json` is the pinned model catalog. Model IDs, revisions, sizes, and hashes are contracts; use `dictate models verify` before trusting a local model.
- The Waybar helper emits one JSON object per run with `text`, `class`, `alt`, `tooltip`, and a listening `percentage`. States are `idle`, `listening`, `transcribing`, `thinking`, `speaking`, and `error`. `listening` must render an explicit `Speak now` label, not only an icon.
- Config and state live under XDG paths resolved by `paths.py`; never hard-code a user's home directory in runtime code. Examples and docs may use `~`.
- `linux/README.md` is the detailed user guide; `linux/TESTING.md` records the verified environment and repeatable checks.

## Work Guidance

- Keep dictation behavior unchanged when working on the assistant, and keep the assistant optional when working on dictation.
- Do not introduce new runtime dependencies; the daemon and CLI are standard-library only.
- Do not enable a GPU ASR backend, and do not remove the `-ng` flag or CPU-only build flags.
- Prefer editing the marked dictate block over rewriting a user's whole Hyprland config.
- When changing install behavior, update `install.sh` help, `linux/README.md`, and the root README install snippet together.
- When changing the Waybar contract, update both the helper and the documented config/CSS example.
- Update `linux/TESTING.md` when the verified matrix, test count, or required environment changes.

## Verification

```sh
PYTHONPATH=linux python3 -m unittest discover -s linux/tests
python3 -m py_compile linux/dictate_unlimited/*.py linux/waybar/dictate-assistant-waybar
./linux/dictate doctor
./linux/dictate assistant doctor   # assistant/LLM/TTS paths
```

For packaging changes, also run `bash -n linux/install.sh` and inspect `git diff -- linux/hyprland.conf.example linux/README.md`.
